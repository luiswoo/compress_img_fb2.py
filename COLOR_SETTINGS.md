# Справка по цветовым настройкам compress_img_fb2.py

Скрипт делит все изображения на две группы и обрабатывает их по-разному:

| Группа | Куда сохраняется | Настройки |
|---|---|---|
| **Цветные** (R, G, B различаются) | JPEG `quality` или PNG-`colors` (выбирается меньший) | `quality`, `colors` |
| **Монохромные** (серый, ч/б) **с прозрачностью** | PNG, режим зависит от `mono_quantize` | `mono_quantize`, `mono_colors` |
| **Монохромные без прозрачности** | как цветные (JPEG/PNG авто-выбор) | `quality`, `colors` |

Ниже — каждый параметр, что он делает и примеры.

---

## tolerance (порог цветности)

**Что делает.** Картинка считается цветной, если для хотя бы одного
проверенного пикселя `|R-G| > tolerance` или `|R-B| > tolerance` или `|G-B| > tolerance`.
Для честного серого R=G=B, поэтому оно остаётся «монохромным».

**Проблема, которую он решает.** Серая картинка, когда-то побывавшая в JPEG,
получает шум: каналы отличаются на 3–15 единиц. При низком tolerance она
ошибочно считается цветной и уходит на белый фон в JPEG (прозрачность теряется,
размер растёт). PNG без потерь такого шума не имеет.

**Рекомендуемые значения:**

| Источник изображений | tolerance |
|---|---|
| Только «чистые» PNG (рендеры, схемы) | 3–5 |
| Смешанный архив, возможны JPEG | 12–15 |
| Сканы с лёгким тонированием, которые хотите сохранить цветными | не выше 8–10 |

> Пример из практики: «чёрная» линия после JPEG имела каналы не 0/0/0, а,
> скажем, 12/10/8 — при `tolerance 3` картинка уходила в цветную ветку,
> при `tolerance 15` корректно определялась как монохромная.

## sample_size

Сколько пикселей случайно проверяется для определения цветности
(при больших картинках). 5000 — нормально для типичных иллюстраций;
поднимите до 20000, если боитесь, что цветные «примеси» (контуры сглаживания)
не попадут в выборку и серое с цветными краями будет ошибочно принято за моно.

## mono_quantize (режим монохромных с прозрачностью)

| Значение | Что получается | Когда использовать |
|---|---|---|
| `LA` | grayscale+alpha PNG, **без потерь**: все 256 градаций серого и прозрачность | Градиенты, мягкие тени, качество важнее размера |
| `FASTOCTREE` | PNG с палитрой, быстрый | Компромисс качество/размер; всегда доступен |
| `LIBIMAGEQUANT` | PNG с палитрой, лучшее качество квантования | Если библиотека доступна в Pillow |
| `MEDIANCUT` | PNG с палитрой | Только без прозрачности (для RGBA автоматически fallback) |

## mono_colors (число цветов палитры)

Значимо **только если mono_quantize ≠ LA** — LA вообще не квантует.

| Значение | Эффект |
|---|---|
| 32 | Максимальная экономия; на градиентах заметен бандинг |
| 128 | Компромисс; бандинг почти незаметен на типичных иллюстрациях |
| 256 | Максимум качества; файл может быть в 2–3 раза больше, чем при 128 |

## Готовые рецепты (примеры команд)

**1. Книга с ч/б иллюстрациями и градациями серого (макс. качество):**
```
python compress_img_fb2.py book.fb2 --tolerance 15 --mono-quantize LA
```

**2. То же, но компактнее:**
```
python compress_img_fb2.py book.fb2 --tolerance 15 \
    --mono-quantize FASTOCTREE --mono-colors 128
```

**3. Смешанная книга (обложки цветные, рисунки серые), JPEG-шум:**
```
python compress_img_fb2.py book.fb2 --tolerance 15 \
    -q 85 -c 128 --mono-quantize FASTOCTREE --mono-colors 128
```

**4. Максимальное сжатие цветных, серым — только 32 оттенка:**
```
python compress_img_fb2.py book.fb2 -q 60 -c 96 \
    --tolerance 15 --mono-quantize FASTOCTREE --mono-colors 32
```

**5. Библиотека целиком (оригиналы будут заменены!):**
```
python compress_img_fb2.py ./library --tolerance 15 --mono-quantize LA
```

**6. Только пережать цветные, моно не трогать палитрой (LA), крупнее картинки:**
```
python compress_img_fb2.py book.fb2 --max-size 1200 --min-size 900 \
    --tolerance 15 --mono-quantize LA
```

## Частые вопросы

**Почему серая картинка попала в JPEG на белом фоне?**
`tolerance` слишком низкий — шум JPEG (или цветной контур сглаживания)
перевалил порог. Поднимите до 12–15.

**LA даёт большие файлы, что делать?**
Перейдите на `FASTOCTREE` с `mono_colors 128` — бандинг на градиентах
почти незаметен, файл заметно меньше.

**Как понять, что картинка классифицирована правильно?**
Смотрите вывод скрипта: для каждого `<binary>` печатается
«Изображение монохромное» / «Изображение цветное» и итоговый формат.

**`-c 0` и `--mono-colors 0` — это одно и то же?**
Нет. `-c` управляет авто-выбором для **цветных** (0 = только JPEG),
`--mono-colors` — палитрой **монохромных** PNG (диапазон 2–256).
