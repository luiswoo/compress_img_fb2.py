# COLOR_SETTINGS.md — настройки и параметры compress_img_fb2.py

Скрипт сжимает и масштабирует изображения в fb2 файле. По умолчанию наибольшая
сторона изображения 800 пикселей, наименьшая 600 пикселей (это максимальное
разрешение по спецификации fb2; если изображение равностороннее (квадратное),
то масштабирование будет по меньшей стороне (min_size); защиты от
непропорциональных параметров разрешения, как 800x1, не предусмотрено).
По умолчанию степень сжатия 85%. За эти настройки соответственно отвечают:
max_size, min_size, quality в настройках внутри файла, либо предопределяются
внешними параметрами.

Скрипт пытается определить в png монохромные изображения с альфа-каналом и
конвертирует их в png; либо конвертируется в jpg или в png (при наличии
значения (1-256) у параметра colors для png), если изображение определено
полноцветным — скрипт сравнивает потенциальный размер файла в обоих форматах
перед сжатием и выбирает наименьший; либо только jpg, если в настройках
указано значение None у параметра colors. За определение цветности png
отвечают параметры tolerance и sample_size (по умолчанию настроено на
ч/б изображения).

---

## Использование

Обработка одного файла:
```
python compress_img_fb2.py "/путь_до_файла/файл.fb2"
```
Создаёт в каталоге с исходным файлом выходной файл с припиской
`compress_файл.fb2`.

Рекурсивная обработка всех fb2 файлов в каталоге с заменой оригинала:
```
python compress_img_fb2.py "/путь_до_каталога"
```

Предопределяющие внешние параметры: `-c N` (количество цветов для PNG, для
автовыбора по размеру между png и jpg — указывать для потенциальной подмены
менее 64 и более 128 цветов смысла особого нет); `-q N` — степень сжатия
изображения.
```
python compress_img_fb2.py -q 60 -c 64 "/путь_до_файла/файл.fb2"
```
— для обработки аниме-образных картинок без градиентов (в более 90% случаев
выбирается jpg).

## Исключение изображений из обработки: `--skip`

Исключение изображений из обработки через внешний параметр `--skip`
(принимает одно правило за раз; разделитель значения — `=` или `:`):

| Правило | Действие | Исключения |
|---|---|---|
| `small[=N]` | Пропускает картинки, площадь которых меньше **N%** от площади области `max_size` × `min_size`, с любым расширением (jpg, png). По умолчанию N=10. | Нет |
| `png` | Пропускает все изображения с расширением png. | Обложка `cover.*` не пропускается |
| `png_mono_alpha` | Пропускает только те png, что были определены как монохромные с альфа-каналом (в jpg такие сильно теряют в читаемости). | Обложка `cover.*` не пропускается; цветные png идут по стандартному конвейеру |

Примеры:
```
python compress_img_fb2.py --skip small book.fb2       # порог по умолчанию 10%
python compress_img_fb2.py --skip small=10 book.fb2    # то же, явно
python compress_img_fb2.py --skip small:10 book.fb2    # то же, через ":"
python compress_img_fb2.py --skip png book.fb2         # все png, кроме cover.*
python compress_img_fb2.py --skip=png book.fb2         # то же через "="
python compress_img_fb2.py --skip png_mono_alpha book.fb2
```

Правило действует во всех режимах, включая `--webp`: пропущенное изображение
остаётся в исходном формате и размере.

За порог `small` отвечает настройка `small_percent` внутри файла
(по умолчанию 10).

## Конвертация всех изображений в webp: `--webp`

```
python compress_img_fb2.py --webp "/путь_до_каталога"
```

Данный формат не соответствует спецификации fb2. При конвертации в webp
доступны только параметры качества (`-q`/`--quality`) и размер сторон
(`--max-size`, `--min-size`).

Поведение режима:
- Все изображения конвертируются **строго в WebP** — без авто-выбора против
  PNG и без разделения на цветные/монохромные.
- Прозрачность сохраняется нативно (альфа-каналом, без заливки фоном); если
  её нет — картинка конвертируется как есть.
- Не используются: `-c`/`--colors`, `--mono-quantize`, `--mono-colors`,
  `--tolerance`, `--sample-size`.

Примеры:
```
python compress_img_fb2.py --webp book.fb2
python compress_img_fb2.py --webp -q 60 book.fb2
```

## Настройки внутри файла (CONFIG)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `max_size` | 800 | Максимальный размер по длинной стороне, px |
| `min_size` | 600 | Минимальный размер по короткой стороне, px |
| `quality` | 85 | Качество JPEG/WebP (1-100) |
| `colors` | 128 | Цветов для PNG авто-выбора (1-256). `None` — только JPEG |
| `mono_quantize` | `"LA"` | Метод для монохромных с прозрачностью: `"LA"` (grayscale+alpha без потерь), `"LIBIMAGEQUANT"`, `"FASTOCTREE"`, `"MEDIANCUT"` |
| `mono_colors` | 32 | Цветов при квантовании монохромных (значимо, если `mono_quantize` != `"LA"`) |
| `tolerance` | 15 | Порог определения цветности: разница R/G/B в тонах 0-255. Поднимите (12-20), если серая картинка определяется как цветная (шум JPEG) |
| `sample_size` | 5000 | Сколько пикселей проверять при определении цветности |
| `webp` | False | `True` — все изображения в WebP (по умолчанию только через `--webp`) |
| `skip` | `[]` | Правила пропуска (задаются только через `--skip`): `"small"`, `"png"`, `"png_mono_alpha"` |
| `small_percent` | 10 | Порог для `small`: площадь картинки меньше N% от площади `max_size` × `min_size` |

Все параметры, не указанные в командной строке, берутся из `CONFIG` в начале
скрипта.

## Полный список внешних параметров

| Параметр | Назначение |
|---|---|
| `path` | Путь до .fb2 файла или каталога |
| `-q`, `--quality N` | Качество JPEG/WebP 1-100 |
| `-c`, `--colors N` | Цветов для PNG авто-выбора 1-256, 0 = только JPEG |
| `--webp` | Все изображения строго в WebP |
| `--skip RULE` | Правило пропуска: `small[=N]`, `png`, `png_mono_alpha` |
| `--mono-quantize M` | Метод квантования монохромных с прозрачностью |
| `--mono-colors N` | Цветов при квантовании монохромных 2-256 |
| `--max-size N` | Максимум по длинной стороне, px |
| `--min-size N` | Минимум по короткой стороне, px |
| `--tolerance N` | Порог определения цветности 0-255 |
| `--sample-size N` | Сколько пикселей проверять при определении цветности |

# Справка по цветовым настройкам compress_img_fb2.py

Скрипт делит все изображения на две группы и обрабатывает их по-разному:

| Группа | Куда сохраняется | Настройки |
|---|---|---|
| **Цветные** (R, G, B различаются) | JPEG `quality` или PNG-`colors` (выбирается меньший) | `quality`, `colors` |
| **Монохромные** (серый, ч/б) **с прозрачностью** | PNG, режим зависит от `mono_quantize` | `mono_quantize`, `mono_colors` |
| **Монохромные без прозрачности** | как цветные (JPEG/PNG авто-выбор) | `quality`, `colors` |

Ниже — каждый параметр, что он делает и примеры.

---

## tolerance (порог цветности)

**Что делает.** Картинка считается цветной, если для хотя бы одного
проверенного пикселя `|R-G| > tolerance` или `|R-B| > tolerance` или `|G-B| > tolerance`.
Для честного серого R=G=B, поэтому оно остаётся «монохромным».

**Проблема, которую он решает.** Серая картинка, когда-то побывавшая в JPEG,
получает шум: каналы отличаются на 3–15 единиц. При низком tolerance она
ошибочно считается цветной и уходит на белый фон в JPEG (прозрачность теряется,
размер растёт). PNG без потерь такого шума не имеет.

**Рекомендуемые значения:**

| Источник изображений | tolerance |
|---|---|
| Только «чистые» PNG (рендеры, схемы) | 3–5 |
| Смешанный архив, возможны JPEG | 12–15 |
| Сканы с лёгким тонированием, которые хотите сохранить цветными | не выше 8–10 |

> Пример из практики: «чёрная» линия после JPEG имела каналы не 0/0/0, а,
> скажем, 12/10/8 — при `tolerance 3` картинка уходила в цветную ветку,
> при `tolerance 15` корректно определялась как монохромная.

## sample_size

Сколько пикселей случайно проверяется для определения цветности
(при больших картинках). 5000 — нормально для типичных иллюстраций;
поднимите до 20000, если боитесь, что цветные «примеси» (контуры сглаживания)
не попадут в выборку и серое с цветными краями будет ошибочно принято за моно.

## mono_quantize (режим монохромных с прозрачностью)

| Значение | Что получается | Когда использовать |
|---|---|---|
| `LA` | grayscale+alpha PNG, **без потерь**: все 256 градаций серого и прозрачность | Градиенты, мягкие тени, качество важнее размера |
| `FASTOCTREE` | PNG с палитрой, быстрый | Компромисс качество/размер; всегда доступен |
| `LIBIMAGEQUANT` | PNG с палитрой, лучшее качество квантования | Если библиотека доступна в Pillow |
| `MEDIANCUT` | PNG с палитрой | Только без прозрачности (для RGBA автоматически fallback) |

## mono_colors (число цветов палитры)

Значимо **только если mono_quantize ≠ LA** — LA вообще не квантует.

| Значение | Эффект |
|---|---|
| 32 | Максимальная экономия; на градиентах заметен бандинг |
| 128 | Компромисс; бандинг почти незаметен на типичных иллюстрациях |
| 256 | Максимум качества; файл может быть в 2–3 раза больше, чем при 128 |

## Готовые рецепты (примеры команд)

**1. Книга с ч/б иллюстрациями и градациями серого (макс. качество):**
```
python compress_img_fb2.py book.fb2 --tolerance 15 --mono-quantize LA
```

**2. То же, но компактнее:**
```
python compress_img_fb2.py book.fb2 --tolerance 15 \
    --mono-quantize FASTOCTREE --mono-colors 128
```

**3. Смешанная книга (обложки цветные, рисунки серые), JPEG-шум:**
```
python compress_img_fb2.py book.fb2 --tolerance 15 \
    -q 85 -c 128 --mono-quantize FASTOCTREE --mono-colors 128
```

**4. Максимальное сжатие цветных, серым — только 32 оттенка:**
```
python compress_img_fb2.py book.fb2 -q 60 -c 96 \
    --tolerance 15 --mono-quantize FASTOCTREE --mono-colors 32
```

**5. Библиотека целиком (оригиналы будут заменены!):**
```
python compress_img_fb2.py ./library --tolerance 15 --mono-quantize LA
```

**6. Только пережать цветные, моно не трогать палитрой (LA), крупнее картинки:**
```
python compress_img_fb2.py book.fb2 --max-size 1200 --min-size 900 \
    --tolerance 15 --mono-quantize LA
```

## Частые вопросы

**Почему серая картинка попала в JPEG на белом фоне?**
`tolerance` слишком низкий — шум JPEG (или цветной контур сглаживания)
перевалил порог. Поднимите до 12–15.

**LA даёт большие файлы, что делать?**
Перейдите на `FASTOCTREE` с `mono_colors 128` — бандинг на градиентах
почти незаметен, файл заметно меньше.

**Как понять, что картинка классифицирована правильно?**
Смотрите вывод скрипта: для каждого `<binary>` печатается
«Изображение монохромное» / «Изображение цветное» и итоговый формат.

**`-c 0` и `--mono-colors 0` — это одно и то же?**
Нет. `-c` управляет авто-выбором для **цветных** (0 = только JPEG),
`--mono-colors` — палитрой **монохромных** PNG (диапазон 2–256).
